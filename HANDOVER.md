## 3. UI edge-case pass — 2026-10-20

Closes out the seven known-wrong items in `NEXT_ASSISTANT_PROMPT.md` §1 and works through the §4 edge-case list.

- **Typography.** Every DOM label now respects the 15px floor (hint bar, workflow panel, Vol/Pan labels, ruler, section markers, status line, `kbd` chips). Canvas text — ruler numbers, section markers, piano-roll labels, the `CUT` badge and the gate-shaper empty state — is drawn at 15px with fit guards, so a long name is shortened only where it would otherwise collide.
- **Touch targets.** Under `(pointer: coarse), (hover: none)` every control is at least 44×44px: M/S/× track buttons, clip ⋯/× buttons, section-marker ×, channel LEDs, and the sliders' hit areas. Loop-handle and marker-× zones span the full ruler height, so a thumb cannot miss them.
- **Long press.** On touch, a long press on a clip opens the clip menu and a long press on a track header starts rename; there is no hover-only path left.
- **Names.** Library cards clamp to two lines, track titles use the flexible title slot, and mixer strips show vertical names; the full name stays available in the tooltip/long-press.
- **Layout.** `.fl-upper-dock.all-collapsed` reclaims the dead band above the Playlist, pan sliders fit the header grid, the Note 3 portrait header is one compact transport row plus one window-tab row, the piano-roll dock clamps to `min(340px, 44vh)`, and short screens shrink the chrome instead of scrolling.
- **Vertical scrolling.** A custom playlist rail (`#vscroll-rail`, `role="scrollbar"`, pointer drag plus arrow/Page/Home/End keys) replaces native vertical range inputs, which render inconsistently on Chrome 95-class devices. It is the only way to reach tracks 33+ in tall projects.
- **Clip menu.** Grouped sections (Edit Segment / Arrange / Flags) with accurate shortcut chips (`Ctrl+D`, `R`, `Del`) and a new Chop 1-Bar action; hints are only shown where the key does exactly the same thing.
- **Robustness.** A malformed `.dawproj.json` no longer throws, `saveProject()` reports honestly when `localStorage` refuses the write, the pattern-preview interval no longer stacks, `snapshot()` deep-copies assets so undo restores channel mute state, BPM input clamps `0` / negative / `999` / text into 20–260, shortcuts stay quiet while a dialog is open, a `storage` event refreshes the project list in a second tab, and the AudioContext resumes on `visibilitychange`.

## 4. Toolbar rebuild — 2026-10-20 (this pass)

The phone toolbar had collapsed into two popover buttons (`Tools`, `More`) whose cards floated over the Playlist with no scrim or anchor, hid window switching in an overflow menu, and hid the editing tools exactly where they were needed. That structure is gone.

- **Permanent tool strip.** The eight tools (Draw/Paint/Slice/Delete/Mute/Slip/Select/Pan) are on the toolbar row at every width, icon-first with the active tool lit. Their labels appear from 1361px (where the whole row, snap, history, the ✂ menu and the six window buttons still fit one line) and the `kbd` chips from 1601px on hover-capable desktop pointers only. Below 360px the strip wraps to four per row so no target drops under 44px.
- **Permanent window strip.** One row of six 44×44 icon buttons — Library, Step Rack, Piano Roll, Mixer, Pads (Trellis), Clip Insp — always visible (300px including gaps, so it fits a 320px screen). Lit means open. They keep the existing `#btn-toggle-*` ids and handlers as the single source of truth; `#mobile-window-switcher` is deleted, so nothing duplicates it any more.
- **One `✂` menu, destructive actions only.** Split @ Playhead, Cut Half, Chop 1-Beat, Chop 1-Bar, Auto-Slice, Duplicate, Reverse, Delete Clip, Clear Playlist, in three labelled groups with 44px rows, disabled (`aria-disabled`) when nothing is selected. No window toggles, no pattern controls, no undo/redo.
- **Options is a real sheet.** Title bar + ✕ and four sections: Theme (swatches + full list), Appearance (wallpaper, accent, background), Project (name, Save, Open) and Audio (Upload Stems, Export Track). It is a fixed, right-aligned, viewport-bound panel on desktop and a bottom sheet over the scrim on phones (max 80dvh, internal scroll, drag handle). It no longer moves between the header and the tool bar.
- **Every popover is anchored and scrimmed.** One `#popover-scrim` dims the workspace behind any toolbar or header panel; panels are `position: fixed`, aligned to their trigger's edge, clamped inside the viewport, flipped above the trigger when there is no room below, and closed by Escape, tap-outside, the scrim and their own ✕. `aria-expanded` is kept on every trigger, focus returns to the trigger on close, and nothing is focus-trapped.
- **One state.** All window buttons route through `toggleStudioWindow()` / `focusWorkspaceWindow()`: on phones a tap brings that window to the front and a second tap returns to the Playlist, so the lit button always describes what is on screen. F5–F9 click the same buttons. Crossing the 760px breakpoint closes every popover, so nothing is left open and orphaned.
- **Everything stays reachable.** `Pattern` + `Paint Pat` moved into the Step Rack header (the duplicate “To Playlist” stamp button was removed: one stamp action), `Gate` moved into the Mixer header next to its FX slot 6, undo/redo/marker are icon buttons beside the ✂ menu, the zoom slider sits with the timeline scroll controls, and the layout-preset (F5) and shortcuts (F1) buttons are icon buttons in the top bar.
- **Phones show one window at a time.** The first paint brings the Playlist to the front and collapses the other panels, matching the one-window model; the Library is the first button in the strip. Desktop and tablet keep Library + Playlist as before.
